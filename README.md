# Poise — AI interview simulator

Poise is a career interview simulator. You pick a role, an interviewer, and a difficulty, answer five questions in a calm interview room, and get a report that reads your **content** (what you said) and your **presence** (how you showed up) as one story.

This repository is the **frontend text MVP**. Everything works end to end, but the AI backend, auth, video analysis, and storage are mocked locally so the product and design can be reviewed and demoed.

---

## Quick start

```bash
npm install
npm run dev      # http://localhost:3000
```

Other scripts:

```bash
npm run lint     # ESLint
npm run build    # production build
npm start        # run the production build
node scripts/shots.mjs   # Playwright screenshots + full 5-answer flow (needs a dev server + Microsoft Edge)
```

`scripts/shots.mjs` drives Edge through `playwright-core`, walks setup → interview → report → history, writes screenshots to `shots/`, and prints any console errors.

## What is mocked

### Auth
`/sign-in` accepts any non-empty email and password (and a name in sign-up mode), waits a beat, stores a demo user, and sends you to `/setup`. There is no session token, no Cognito, and no route protection beyond "is a demo user stored".

**Later:** replace the `saveUser` call with Amplify Auth against Cognito and gate `(app)` routes with a real session.

### Interview questions
`getQuestions()` in `src/lib/data.ts` builds five questions from the chosen role, interview type, and persona using local templates with `{role}` / `{topic}` substitution and a small role-specific bank. Answers are not sent anywhere.

### Answer evaluation
`evaluateAnswer()` in `src/lib/interview.ts` scores each answer heuristically:

- length and specificity signals (numbers, transitions, named outcomes)
- keyword overlap with the question
- structure markers ("first", "then", "because", "result")
- per-difficulty baseline and spread

It returns the same `Evaluation` shape the real model is expected to return, so the UI does not change when the backend lands. Strong, specific answers land around 80–85 content.

### Presence metrics
`generatePresenceMetrics(seed)` returns deterministic-per-session mock numbers:

```ts
{
  eyeContactPercent: number,
  posture: { slouchPercent: number, leanEvents: number },
  gestures: { fidgetCount: number, handsNearFaceCount: number },
}
```

These exact keys (`eyeContactPercent`, `posture.slouchPercent`, `posture.leanEvents`, `gestures.fidgetCount`, `gestures.handsNearFaceCount`) must be preserved: they are the agreed hand-off shape from MediaPipe. The camera preview in `src/components/camera-preview.tsx` is a **real** `getUserMedia` stream with permission, denied, and error states. Nothing is recorded or uploaded.

**Now:** MediaPipe presence tracking runs entirely in the browser. See the `presence.ts` and `use-presence.ts` hooks for the implementation. The tracker returns `BodyLanguageMetrics` from live camera frames only; when the camera is unavailable the mock fallback runs. The mock computes the same `bodyLanguageMetrics` shape from a deterministic hash so the report UI never breaks when presence data is "not measured". The `use-presence` hook also gracefully stops the stream and clears intervals on unmount and interview end.

### Report
`buildReport()` blends content and presence into an overall readiness score (78% content / 22% presence), derives dimension summaries, strengths, improvements, presence notes, and three next steps. Sample reports are generated by `createSampleReports()` so the landing page, `/history`, and `/report/sample_2` are populated on first visit.

### Persistence
Everything lives in the browser.

| Key | Storage | Contents |
| --- | --- | --- |
| `poise.user.v1` | `localStorage` | `{ name, email }` |
| `poise.history.v1` | `localStorage` | `Report[]`, seeded with samples on first read |
| `poise.last-config.v1` | `localStorage` | Last setup form values |
| `poise.draft.v1` | `sessionStorage` | In-progress `InterviewSession` |

The draft intentionally uses `sessionStorage`: an in-progress interview should not survive a new tab, and using `localStorage` previously caused `/interview` to resurrect stale drafts.

Storage reads go through `useSyncExternalStore` hooks in `src/lib/use-storage.ts` and a custom `poise:storage-change` event, so the UI stays in sync across tabs without `setState` inside effects.

To reset the demo: clear site data, or run `localStorage.clear()` in the console. Deleting `poise.history.v1` re-seeds the samples.

## MediaPipe presence tracking

The MediaPipe pipeline runs entirely in the browser — video frames never leave the client device.

### Models + WASM

- Download the three model files into `public/mediapipe/models`:
  - `face_landmarker.task` (face mesh + orientation)
  - `pose_landmarker_lite.task` (pose + posture)
  - `hand_landmarker.task` (hand landmarks)
- Copy all `.wasm` files from `node_modules/@mediapipe/tasks-vision/wasm` into `public/mediapipe/wasm` (self-hosted so the demo does not depend on a CDN).

See `scripts/make-face-video.ps1` for a quick way to generate a test video fixture, and `scripts/_face-probe.mjs` / `scripts/_face-probe2.mjs` for integration smoke tests.

### Tracking order

1. **Eye contact** — Face Landmarker with `outputFacialTransformationMatrixes: false`. The nose tip offset relative to the eye line and the nose-to-chin ratio are used to estimate head yaw and pitch. A sample counts as "facing camera" when yaw ≤ ±20° and pitch is between ~24% and ~62% of eye-to-chin height. `eyeContactPercent = facingSamples / validSamples * 100`.

2. **Posture** — Pose Landmarker. The first ~5 seconds build a baseline: the nose-to-shoulder-gap and the shoulder-midpoint x-position. After calibration, slouch is measured as the gap shrinking below ~86% of baseline; a "lean event" is when the shoulder midpoint drifts >12% of shoulder width from baseline for >2 seconds. Output `slouchPercent` and `leanEvents`.

3. **Hands** — Hand Landmarker (`numHands: 2`). "Hands near face" = wrist within ~85% of the face width from the nose, debounced at 1.5 s. "Fidget" = fast wrist displacement (>32% of shoulder width) debounced at 1.2 s. Output `fidgetCount` and `handsNearFaceCount`.

### Output contract (must not change)

```json
{
  "eyeContactPercent": 62,
  "posture": { "slouchPercent": 18, "leanEvents": 3 },
  "gestures": { "fidgetCount": 12, "handsNearFaceCount": 4 }
}
```

The `presence.ts` module returns these exact keys. When the camera is offline or a model fails to load, the fallback `generatePresenceMetrics(seed)` from the mock is used unchanged, so `buildReport()` and the report UI never see a different shape.

### `use-presence` hook

```tsx
import { usePresence } from "@/lib/use-presence";

export default function InterviewRoom() {
  const { videoRef, cameraState, trackerState, live, start, stop, snapshot } = usePresence();
  // start() requests camera + MediaPipe init.
  // stop() releases tracks and the tracker.
  // snapshot() → BodyLanguageMetrics | null (null when not measured).
}
```

- The hook is lazy: the MediaPipe bundle and models only import once the student clicks "Enable camera".
- The camera stream is `getUserMedia({ video: { width: 640, height: 480 }, audio: false })`.
- Permission denied → UI shows a message and the interview continues without presence data (mock fallback).
- The tracker samples every 500 ms (`SAMPLE_INTERVAL_MS`). It skips ticks if the video is not ready (`readyState < 2`).
- Cleanup: `clearInterval`, `stream.getTracks().forEach(t => t.stop())`, and model `close()` on unmount and interview end.

### Wiring into the interview room

In `src/app/interview/page.tsx`, when the interview ends (`isComplete`):

```tsx
const measured = presence.snapshot();
setPresenceMeasured(measured !== null);
presence.stop();
const metrics = measured ?? generatePresenceMetrics(result.session.id);
const report = buildReport(result.session, metrics, { durationSeconds });
```

If presence was measured from the camera, `measured.metrics` is used. If the camera was off or failed, the deterministic mock is a sound fallback — the report still renders with a full set of scores and presence notes.

### Running MediaPipe on real hardware

Point the camera at your face in typical interview lighting. Avoid backlighting and extreme close-ups. The tracker is tolerant of glasses and natural facial hair but may blink if the face moves quickly out of frame. The `SAMPLE_INTERVAL_MS = 500` means there's a 2-second lag before the numbers settle, which is fine for an interview-room experience.

### Dev / test without a physical camera

Use Playwright with `--use-fake-ui-for-media-stream --use-fake-device-for-media-stream` and `--use-file-for-fake-video-capture=<path-to-y4m>`. The smoke test `scripts/presence-smoke.mjs` proves the tracker loads, starts sampling, and still renders a report when no face is in frame.

### Known limitations

- The tracker needs a minimum of ~8 face samples (about 4 seconds at 500 ms) before a baseline is calibrated.
- Very small faces (camera far away) or extreme head turns may produce noisy estimates.
- The hand tracker works best when hands are visible; crossed arms or obscured wrists reduce `handsNearFaceCount` and `fidgetCount`.
- Models are self-hosted; they are ~20–30 MB total (WASM + task files). The first load may take a few seconds on slow connections.

## Wiring the real API

The mock seam is deliberately narrow. Keep the components as they are and replace these functions:

| Mock function | Becomes | Depends on |
|---|---|---|
| `createSession(config)` | `POST /interview/start` | Aadit's API URL |
| `submitAnswer(session, answer)` | `POST /interview/answer` | Aadit + Dheeraj |
| `generatePresenceMetrics(seed)` | MediaPipe aggregation in the browser → `BodyLanguageMetrics` | Nobody (client-side only) |
| `buildReport(session, metrics)` | `POST /interview/report` (sends `bodyLanguageMetrics`) | Aadit + Dheeraj |
| `getHistory()` / `saveReport()` | `GET /interviews?userId=` | Aadit |
| `saveUser()` | Cognito session | Aadit (user pool IDs) |

`src/lib/types.ts` is the contract: `InterviewConfig`, `InterviewSession`, `InterviewQuestion`, `Evaluation`, `Report`, `BodyLanguageMetrics`. `src/lib/interview.ts` and `src/lib/store.ts` are the only files that need to change shape when the backend arrives.

## Design system

Warm paper background, near-black ink, lime/coral/lilac accents, Instrument Serif display type against Manrope body text. Tokens, animations, and utilities live in `src/app/globals.css` (Tailwind v4 `@theme`). Shared primitives are in `src/components/ui`, and `src/components/app-shell.tsx` provides the sidebar/mobile workspace chrome.

The report is intentionally one read top to bottom: verdict → content vs presence → what stuck / what to tighten → presence in detail → next rehearsal → transcript.
